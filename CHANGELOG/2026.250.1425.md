# 2026.250.1425 — appium: add the session method (Cutover E E-5)

## Summary

Adds the session method to the appium verb (plan nested-capture-architecture.md, Cutover E, unit 5): the DETACHED device-side screen-recording bracket — Appium startRecordingScreen/stopRecordingScreen bracketing the plan run, evidence rows via the shared envelope. It is implemented over the runner's GENERIC background-session service (plugin-check's compiled-in verb:session seam); NO core changes — the fifth catalog verb joining the session model.

- **schema/appium.cue** — session joined the method enum; new per-verb modifiers action/time_limit/fps/video_type/session_id/state_dir/artifact_dir/log_dir/venue/phase; params/cue_types_gen.go regenerated by the documented cue exp gengotypes pipeline (package params + @go(params) wrapper + the spec schemagen yaml-retag transform — byte-identical regeneration proven on the pre-change schema).
- **session_method.go** — the provider-side dispatch: runSession (start|stop|status), buildSessionSpawn (this plugin's OWN binary in recorder mode + the CHARLY_APPIUM_* env), and submission over the EXISTING InvokeProvider reverse leg — class verb, word session, ops.OpExecute. The provider spawns no process, resolves nothing against the Appium server, and knows no transport. Plan-step sessions fall back to session_id "default" + a provider-owned temp state dir.
- **recorder.go** — the detached recorder engine: polls the persisted Appium session file (the plan's session-create step writes it — box+instance key it) for the WebDriver session id + base URL, opens the bracket (start_recording_screen, timeLimit ALWAYS sent — Appium's own default is only 180s), re-brackets when the session is recreated mid-run or when the recording cap approaches (80% preemptive rotation so a phase longer than the cap keeps coverage), and on SIGTERM/SIGINT pulls the video (stop_recording_screen → base64 MP4) into the evidence artifact dir and finalizes the deterministic FINAL marker + the shared #EvidenceRow row.json (instrument/origin/verb/segment/artifact).
- **cmd/serve** — hidden recorder mode (CHARLY_APPIUM_RECORDER=1) on the existing binary.
- **provider.go** — session dispatched before the method switch (the recorder owns the device bracket); checkEnv gains venue for evidence-row provenance.
- **ADE plan** — charly.yml gains five ordered lifecycle checks (appium-session-create → appium-session-start → appium-session-status → appium-session-stop → appium-session-delete) exercising the method against a live Appium server, plus the session method in the description.
- **go.mod** — sdk v0.2026234.347 → v0.2026248.1237, spec v0.2026232.520 → v0.2026248.1234 (the session seam's CheckContext.InvokeProvider contract; the same pair plugin-vnc consumes).

A NEW test fixture proves the changed runtime path over a real wire: recorder_test.go — a fake WebDriver session (an httptest server speaking the W3C recording endpoints) — runs the recorder end to end: bracket open (timeLimit always in the start body) → pull → MP4 artifact → FINAL + row.json, plus the session-recreation re-bracket, the recording-cap rotation, and the honest no-session finalize.
