# 2026.251.0541 — fix(appium): stamp the session-file path into the recorder spawn env (E-5 R1)

## Summary

E-5 R1 seam fix (Cutover E): the detached check-bed appium recorder re-derived its session-file path (`~/.cache/charly/appium/sessions/<box>.json`) via `os.UserHomeDir()`/`XDG_CACHE_HOME` **in its own spawn env**, while the plan's `appium-session-create` writes that file **in the plugin-serve env**. Under divergent envs the recorder polls a path the plan never touches → it opened **ZERO recording brackets** and every E-5 run finalized `segments=0 bytes=0`, so the run's evidence phase failed with `source_artifact empty` (transcode exit 1) — reproducible on check-android-emulator-pod 2026.251.0347 **and** 2026.251.0421 (the latter with a pre-cleared session cache: recorder.log had 4 lines, 0 start brackets, while `appium-session-create` PASSed and the W3C verbs worked through the live handle).

**Fix**: `buildSessionSpawn` now stamps `CHARLY_APPIUM_SESSION_FILE` with `appiumSessionPath(env.Box, env.Instance)` resolved **in the serve env** — the exact path the plan's session-create writes — and the recorder (`runBracketLoop`) prefers the stamped path over its own re-derived one (`loadAppiumSessionPath`). Cross-process env agreement is enforced by contract, not by hoping HOME/XDG agree.
