# 2026.251.0543 — test: prove the persisted appium session handle is shared across all consumers (E-5 R1)

## Summary

The E-5 appium fixture on check-android-emulator-pod requires ONE WebDriver session
handle end-to-end: the bed's session-create → launch → find → stop → delete steps
plus the detached screen recorder must all resolve the same session id. This test
proves the on-disk handle contract that makes that possible:

- the plan's `appium session-create` persists `~/.cache/charly/appium/sessions/<image>.json`;
- every later consumer resolves the SAME session id + base URL from that file: the
  in-plan verb path (`resolveW3CSession`, used by find/click/app-start-activity/...)
  and the detached recorder path (`loadAppiumSession`, polled by recorder.go);
- image-key isolation (one bed's handle never leaks into another's key);
- the 0600 file permission contract (the session id is a bearer token for the live
  Appium server's API).

Test-only change — no runtime behavior change, no pin bump needed for consumers
(the bed keeps v2026.250.1425).
