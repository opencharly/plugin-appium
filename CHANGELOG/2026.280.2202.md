## Summary

`plugin-appium`'s plugin schema header tells its reader how the Go params struct is generated. It said
"(driven by `task cue:gen`, …)" — an **umbrella Taskfile target that no longer exists**. This repo
carries that stale sentence in `candy/plugin-appium/schema/appium.cue`, and it is a PUBLISHED
surface: `charly docs generate` renders each plugin's schema into
`docs/src/content/docs/reference/plugin/<plugin>/plugin-*.md`.

**The issue's own prescribed replacement is measurably false for these repos, so it is not
applied.** `opencharly/plugin-adb#10` says the comment "should read `charly task cue-gen` — the spec
repo's task, which is what actually drives gengotypes now". But inside a plugin repo:

```
$ charly task list
no tasks declared
```

A plugin repo declares no `task:` entities, so that verb can drive nothing here; it is the **spec**
repo's task (`spec/charly.yml`'s `cue-gen:`) for spec's own schema, and it regenerates
`spec/cue_types_gen.go`. The plugin-side mechanism is the same pipeline with `-pkg=params`, run in
the plugin's own repo — recorded in `plugin-adb/CHANGELOG/2026.250.1429.md` ("schemagen concat
-pkg=params → cue exp gengotypes → retag") and stated by `/charly-internals:plugin`. The fix names
that mechanism, and the retired target name is gone.
