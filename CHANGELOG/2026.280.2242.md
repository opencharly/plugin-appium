## Summary

`plugin-appium`'s plugin schema header documents how the Go params struct is generated, and that comment is
a **published** surface: `charly docs generate` renders each plugin's schema into
`docs/src/content/docs/reference/plugin/<plugin>/plugin-*.md`.

Its lineage is three revisions deep, and **this PR is the third**:

1. It read "(driven by `task cue:gen`, …)" — an **umbrella Taskfile target that no longer exists**.
   The merged sweep PR replaced that wording.
2. That replacement named a checkout-relative, non-`charly` recipe: `internal/schemagen -mode=concat
   -pkg=params` "in opencharly/spec", then `cue exp gengotypes`, then `-mode=retag`. R4a forbids
   exactly that on a published page — every command a reader is told to run must work with nothing
   but the `charly` binary installed, with no repo-relative path and no `cd` into a checkout.
   **This PR retires that wording.**
3. What ships now states the mechanism: this file is concatenated under a `package params` +
   `@go(params)` header and the Go struct is generated from it, and the generated file must never be
   hand-edited. The runnable recipe lives in the owning skill `/charly-internals:plugin`, where an
   author regenerating params actually looks.

**The issue's own prescribed replacement is measurably false for these repos, so it is not
applied.** `opencharly/plugin-adb#10` says the comment "should read `charly task cue-gen` — the spec
repo's task, which is what actually drives gengotypes now". Inside a plugin repo:

```
$ charly task list
no tasks declared
```

A plugin repo declares no `task:` entities, so that verb can drive nothing here; it is the **spec**
repo's task, and it regenerates `spec/cue_types_gen.go`. The tooling that produces THIS repo's
params lives in the `opencharly/spec` checkout and is run FROM there AGAINST this plugin's schema
(which is exactly what the proof below does); the plugin repo carries the schema, not the tooling.

**The corrected comment states the mechanism, not a runnable path.** It says this file is
concatenated under a `package params` + `@go(params)` header and the Go struct is generated from it,
and keeps the warning a reader needs — never hand-edit the generated file. Naming the spec
checkout's path or a non-`charly` command on a public plugin page is the R4a defect the operator
forbids, so the *recipe* is not on that page; the exact tooling steps live in the owning skill
(`/charly-internals:plugin`), which is where an author regenerating params looks.
